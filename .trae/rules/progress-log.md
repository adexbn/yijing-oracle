# 过程与进展必须落文件

对话上下文随时可能被压缩或更换模型，**只有落在文件里的状态能活下来**。因此在本项目中：

1. 每完成一步实质改动（改代码、改配置、跑通一次验证、定位一个坑），都要把结果写进仓库根的
   `DEV_STATUS.md`，而不是只在对话里汇报。
2. 重大进展记录成文档：更新 `DEV_STATUS.md` 的「当前状态一览」表，并在「进展日志」表尾
   追加一行 —— 日期 / 提交号 / 做了什么 / 验证方式。
3. 踩到新坑（编译错误、CI 限制、工具不可用），补进 `DEV_STATUS.md` 的「事故与坑」表，
   写清现象 + 根因 + 绕法，方便下次直接跳过。
4. 汇报结论时必须标明是**已验证**还是**估计**；给数字必须带口径（哪批数据、多少条、
   是否参与过调参），不要把估计值说成已验证结论。
5. 一次任务收尾时，主动检查 `DEV_STATUS.md` 是否已同步；没同步就等于没交付。

维护约定：`DEV_STATUS.md` 只写事实，不写愿望；不确定的事写「待验证」。
